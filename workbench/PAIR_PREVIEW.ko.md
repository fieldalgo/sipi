# 차동선 프리뷰

[English](PAIR_PREVIEW.md)

기존 workbench 서버의 `/pair-preview.html`이 로컬 검토용 진입점입니다.
`python workbench/desktop/main.py --no-browser`를 실행한 뒤 출력된 주소의
마지막 `/`와 `#token=…` 사이에 `pair-preview.html`을 넣습니다. 설치 wheel도
같은 화면을 포함하며 `python -m sipi gui --no-browser`로 실행합니다.
출력된 토큰은 공유하지 않습니다. 웹사이트를 공개하는 명령이 아닙니다.

기존 엔진, LocalTransport/BrowserTransport, `sipi.template-section/1` 입력을
재사용합니다. 동일한 직사각형 도체의 마이크로스트립 및 중앙 배치 스트립라인
차동쌍, 균일한 상수 유전율, 이상적인 접지면과 무손실 준정적 차동·공통
임피던스와 m당 도체 손실(아래 참고)을 다룹니다. 제조 수율, 광대역 규격 적합성,
채널 삽입 손실, 3차원 전이는 지원 범위가 아닙니다. 기존 전체 workbench는 그대로 유지합니다.

치수는 mm로 입력하며 외곽 상자와 공기 높이도 명시합니다. 선폭 역산은 두
선폭을 함께 바꾸고 도체 가장자리 간격을 고정합니다. 기존 유계 검색과 별도
세분 계산이 모두 목표 허용오차를 만족해야 하며 수치 기준을 완화하지 않습니다.
단일 계산은 메시 수렴을 확인하지 않습니다. 역산의 세분 통과도 외곽 수렴의
근거는 아닙니다. 계산 기록에는 최초 요청, 실제 선택 기하, 행렬, 메시,
검색 이력과 엔진 정보가 들어갑니다. 엔진 버전만으로 빌드를 식별할 수 없으므로
검증 기록에는 소스·wheel 해시도 함께 보관합니다.

설계 저장은 현재 기하와 실제 메시를 표준 JSON으로 내려받습니다. 목표 조건이나
결과 저장은 아니므로 계산 기록은 입력 저장 전에 별도로 내보냅니다. 다시 열면
정확한 SI 값과 메시를 유지하지만 결과는 새로 계산해야 합니다. 지원하지 않는
형상·재료 조건은 조용히 제거하지 않고 거부합니다. 입력 편집, 열기 실패, 취소,
계산 실패는 이전 결과를 숨깁니다. 취소가 끝난 다음에 새 계산을 시작합니다.
별도 수집 서버, 사용 추적, 설계 업로드는 추가하지 않았습니다.

저장소 루트에서 실제 Chromium 검증을 실행합니다.

```sh
SIPI_PYTHON=python PYTHONPATH=src node workbench/tests/pair-preview-browser.mjs OUTPUT
```

브라우저 런타임을 별도로 준비했다면 두 번째 인수로 해당 경로를 줍니다. 기존
브라우저 준비 도구가 이 페이지를 복사하고 런타임 표시를 바꿉니다. 과거 엔진으로
현재 코드를 검증했다고 할 수 없으므로 정확한 manifest·소스·wheel·UI 해시를
남겨야 합니다. 검증은 두 실제 계산과 두 100Ω 역산, 정확한 저장·재열기,
편집 무효화, 잘못된 기하, 취소·재시작, 작은 화면 넘침과 외부 요청을 확인합니다.
전체 입력 범위나 모든 브라우저의 지원을 뜻하지 않습니다. 공개 전에는 수치
일치, 독립 물리 기준 대조와 재배포 검토를 별도로 마쳐야 합니다.

## CCL 조건 비교

초기 치수·유전율은 가상 예제이며 특정 업체의 소재 등급이 아닙니다. 소재명과
출처/측정 조건 메모는 사용자 입력 문맥일 뿐 재료법칙·주파수·온도·손실 모델을
선택하지 않습니다. 계산 후 **Keep result as A · start B**로 전체 기록 A를
고정하고 남아 있는 입력을 수정해 B를 계산하거나 선폭을 역산합니다. 표에는
각 선택 기하·계산 종류·목표 검사 상태가 표시됩니다. 역산 선폭은 초기값이
아닌 선택값입니다. 차이는 소재뿐 아니라 기하·메시·목표 조건에도 의존하므로
소재 성능 인증으로 해석하지 않습니다.

입력 편집·열기·실패·취소는 B를 지우고 A는 명시적으로 교체/삭제하거나 페이지를
새로 열기 전까지 보존합니다. A는 메모리 snapshot이며 자동 저장되지 않습니다.
**Export A/B records**는 `sipi.preview-comparison/1` 보고서를 내려받습니다.
`a`, `b` 각각에 원 요청·전체 엔진 결과·소재명/메모가 들어갑니다. 실행용 입력이나
다시 열 수 있는 프로젝트가 아닙니다. 기존 설계 JSON은 그대로이며 소재명/메모,
목표 조건, A/B 결과는 저장하지 않습니다. 설계를 다시 열면 소재 식별을 초기화하므로
문맥을 입력하고 새로 계산합니다. 페이지를 닫기 전에 비교 보고서를 내보내세요.
사용자 소재명의 HTML은 해석하지 않습니다.

실제 브라우저 검증에는 두 단면의 유전율 변경, A 보존/B 정확 내보내기, 메모·
선택 기하·오래된 결과 제거·명시 삭제·마크업 형태 문자의 안전한 표시를 포함합니다.

## 숫자 입력 화살표

위/아래 버튼 또는 키보드 ArrowUp/ArrowDown으로 작은 단위로 조절합니다.
선폭·간격·기판 높이/접지면 간격·검색 선폭 범위는 0.01mm, 구리 두께는
0.001mm, 외곽 상자 폭·공기 높이는 0.1mm, 상대 유전율은 0.1, 목표
임피던스는 1Ω, 목표 허용오차는 0.01Ω씩 바뀝니다. 각 입력의 최솟값은
유지합니다. 유효한 소수값은 여전히 직접 입력할 수 있으며 설계를 열거나
계산된 선폭을 받을 때 증분 단위로 반올림하지 않습니다. 값을 바꾸면
기존과 같이 현재 결과가 무효화됩니다.
터치 화면에서는 화살표 버튼이 넓어져 누르기 쉽습니다.
Tab은 화살표 버튼을 건너뜁니다. 칸에 포커스가 있을 때 ArrowUp/ArrowDown이 같은 일을 합니다.

## 작업별 결과 표시

간결한 작업 화면에서 단면 입력 옆의 두 작업을 구분합니다. **Impedance result**에는
단일 계산의 진행·결과·오류가, **Find trace width**에는 탐색 진행·취소·선택 선폭·
세분 검증·탐색 오류가 표시됩니다. 탐색 성공 시 정확한 선택 선폭을 단면 입력에
반영하며 결과는 목표 입력 옆에 남습니다. 파일 열기·저장 상태는 파일 버튼 옆에 표시됩니다.

넓은 화면에서는 **Impedance result**가 오른쪽 열의 **Calculate impedance** 바로 아래에,
**Find trace width**가 단면도 아래에 목표 입력 네 칸을 한 줄로 두고 놓입니다. 좁은 화면에서는
단면도·입력·임피던스 결과·선폭 찾기 순서로 쌓여 각 결과가 해당 버튼 바로 뒤에 옵니다.

각 상태 줄은 상태를 함께 보여 줍니다. 작업 중에는 도는 표시가, 계산·탐색·저장·열기가 끝나면
초록 줄이, 실패하면 **Error**로 시작하는 빨간 줄이 나옵니다. 양 끝 표에는 선폭 단위(mm)가
적혀 있습니다. 색은 글자 내용을 반복할 뿐 대신하지 않습니다.

키보드로 계산·탐색·저장·열기를 시작하면 작업 중에는 포커스가 **Cancel**로 옮겨 갑니다(Enter로
취소). 작업이 끝나거나 취소되면 포커스는 그 작업을 시작한 버튼으로 돌아옵니다.

목표가 양 끝 임피던스 사이에 없으면 선폭 역산 패널에서 실제 양 끝 선폭(mm)과 차동 임피던스(Ω)를
표로 보여줍니다. 입력을 자동 변경하지 않고 범위·목표·단면을 검토하도록 안내합니다.
두 끝점 표본은 다른 범위에서 목표에 도달할 수 있다는 보장이 아닙니다. 원래 탐색
이력은 실패 상세에서 확인합니다. 편집이나 새 작업은 오래된 결과·오류를 지우며,
명시적으로 보관한 A는 유지됩니다. 수치 탐색·세분 검증 기준은 변경하지 않았습니다.

## 구조 프리셋과 단면도

왼쪽 라이브러리에는 독자 예시 네 가지가 있습니다. Surface pair·Compact surface는
마이크로스트립, Buried pair·Thin core pair는 중앙 배치 스트립라인입니다. 프리셋을
선택하면 모든 단면 치수·Dk·계산 경계가 예시 값으로 바뀌고, 불러오거나 역산에서
결정한 메시는 자동 설정으로 돌아가며 소재 문맥도 예시로 초기화됩니다. 현재 결과와
오류는 지우지만 기준 A와 선폭 목표·범위·허용오차는 유지합니다. 특정 제조사 등급이나
목표 임피던스를 보증하는 값이 아닙니다. 타사 그림·모델 번호·재료 DB는 포함하지 않습니다.

단면도의 W·S·H·T·εr을 누르면 해당 입력으로 이동합니다. Tab 후 Enter나 Space도
사용할 수 있습니다. 그림과 입력은 함께 강조됩니다. 단면 입력 편집이나 선폭 역산
성공 후에는 **Custom dimensions**로 표시됩니다. 저장 설계도 같은 표시로 열리며
정확한 값과 메시를 보존합니다. 프리셋 클릭은 현재 단면을 명시적으로 교체하는 동작입니다.

치수 글씨를 읽기 쉽도록 도식 비율을 제한합니다. 실제 축척 도면이나 제조용 쿠폰이
아닙니다. W는 각 선폭, S는 도체 가장자리 간격, H는 기판 높이 또는 두 접지면의 전체
간격, T는 구리 두께입니다. 스트립라인 도체는 접지면 사이 중앙에 있습니다.
더 많은 엔진 구조는 Full workbench에서 계속 사용할 수 있습니다.

## 도체 손실

**Conductor loss**는 선폭 찾기 아래에 있습니다. 전도율을 MS/m로(풀림 구리 58),
표면 거칠기(매끈함, 또는 RMS 높이를 µm로 주는 경험식 Hammerstad 보정)와 최대
16개의 주파수를 GHz 단위로 쉼표로 구분해 입력합니다. **Calculate conductor
loss**는 기존 공개 엔진 경로만 씁니다. 먼저 일반 `document` 동작으로 현재 단면을
만들고, 저장형 `sipi.transmission-line/8` 선로를 `modes` 진단과 함께
`saved-analyze`로 계산합니다. line/8은 기본으로 panel 도체 전류를 쓰고, 엔진이
기본 panel 제어값(두 쌍 구조 모두 변당 64 panel, 접지 모드 512, 보간 차수 14)을
저장합니다. 화면은 수치 설정을 정하지 않습니다. 트레이스와 접지면은 같은 표면
금속을 쓰며 접지 두께는 구리 두께 T입니다. 선로 길이 1 m, 포트 기준 50 Ω은 표에
보이는 m당 값에 영향을 주지 않습니다.

표는 주파수별로 자기·상호 저항(Ω/m), 차동·공통 도체 감쇠(dB/m), 그리고 두 모드의
유전 감쇠를 별도 열에 보여 줍니다. 감쇠는 엔진의 단일 모드 기여
`alpha_conductor`(Np/m, 20/ln 10으로 환산)이며, 도체 전압 부호가 반대인 모드를
차동 모드로 봅니다. 이 프리뷰는 tan δ = 0이므로 유전 열은 0입니다. 값은 m당
선로 특성이며 종단된 채널의 삽입 손실이 아닙니다.

계산은 보통 수 초 걸립니다(로컬 Linux 빌드에서 세 주파수 기준 프리셋마다 약 5초).
일부 단면은 수십 초가 걸리고, 브라우저 런타임은 첫 계산 때 엔진도 불러옵니다.
상태 줄이 경과 초를 세며 **Cancel**로 멈출 수 있습니다. 도체 모델 범위 밖의
입력(예: 구리 두께에 비해 너무 큰 표피 깊이, T = 0)은 엔진이 거부하고, 빨간
메시지로 표시하며 결과를 남기지 않습니다.

기하·프리셋·재료 메모 변경, 열기, 선폭 찾기, 손실 입력 변경은 손실 결과를 지웁니다.
임피던스 계산도 손실 결과를 지우지만, 손실 계산은 임피던스 결과를 유지합니다.
**Export loss record**는 `sipi-pair-conductor-loss.json`에 기하 요청, 손실 설정,
line/8 원문, 엔진의 `sipi.execution/1` 결과(R, L, G, C, 회로망, modes)와 재료
라벨을 담아 내려받습니다. `execution.input`은 정규화된 line/8 문서이며
`sipi run`으로 다시 계산할 수 있습니다. 손실 설정은 저장 설계에 들어가지 않습니다.
`sipi.template-section/1` 형식은 그대로이며 기존 설계 파일도 그대로 열립니다.
A/B 비교는 지금도 임피던스만 비교합니다.

브라우저 검증 시험은 Surface pair 손실을 계산하고, line/8 입력·panel 제어값·표시
값을 내보낸 엔진 결과와 대조한 뒤 거부되는 주파수, 취소, 편집에 의한 무효화를
확인합니다. 이 확인은 Linux Chromium에서만, 로컬 네이티브 엔진과
`packaging/engine-ref.txt`로 로컬에서 준비한 브라우저 런타임(Pyodide 0.29.5 Worker,
numpy 2.2.5, scipy 1.14.1, shapely 2.0.7) 두 방식으로 했고 전체 검증이 둘 다
통과했습니다. `sipi.transmission-line/8`보다 오래된 엔진으로 준비한 런타임은 손실
계산을 거절하므로 현재 고정점으로 준비하십시오.

Worker에서도 panel 경로가 그대로 실행됩니다. 네 프리셋을 1, 5, 10 GHz로 계산할 때
손실 단계는 약 3.3–3.7초(같은 패키지 버전·BLAS 스레드 1개의 네이티브: 1.6–2.1초)였고,
페이지의 첫 계산에는 엔진을 불러오는 약 7.5초가 더해졌으며, 이후 WebAssembly 힙은
188–270 MB였습니다. 표시된 표는 네이티브와 같았습니다. 엔진과 패키지 버전이 같아도
값이 비트 단위로 같지는 않습니다. R은 행렬 최대 원소 대비 최대 1.4e-13(원소별
1.7e-12), 감쇠는 최대 1.5e-13, C는 최대 1.3e-15, 임피던스는 최대 마지막 자리 1단위 차이였습니다.
네이티브를 일반 BLAS 커널로 강제하면 R 차이가 줄어들어, 남은 차이는 서로 다른 BLAS
커널과 수학 라이브러리 때문으로 봅니다(더 추적하지는 않았습니다). 선폭 찾기는
네이티브의 약 1.5배(템플릿마다 약 2분) 걸렸고 WebAssembly 힙이 약 1.3 GB까지
커지며, 페이지를 다시 불러올 때까지 유지됩니다. 다른 브라우저, 운영체제, 휴대폰은
확인하지 않았습니다.
