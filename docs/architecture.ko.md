# SIPI 제품과 계산 영역의 경계

[English](architecture.md)

상태: `fb3abe6`의 코드를 확인한 책임 범위·추출 설계입니다. 이 문서는 새
배포판·네임스페이스·저장소·웹 경로·릴리스를 만들지 않습니다. 기존 `sipi`
import, CLI, 버전 있는 문서 형식은 유지합니다. SIPI는 제품이고 전송선 설계는
첫 집중 사용 흐름입니다. 계산 라이브러리와 제품의 범위·배포 단위·릴리스 주기는
같을 필요가 없습니다.

## 책임 범위

| 경계 | 소유하는 기능 | 현재 대표 구현 |
| --- | --- | --- |
| 공유 수치 패키지 | 범용 메시·요소·필드 조립·수치 풀이. SIPI 제품에는 의존하지 않음 | [dependencies.json](../dependencies.json)의 외부 `galerkin`, `meshine` |
| 전송선 영역 | 단면·재료·단위 길이당 RLGC 추출·모드·균일 선로 전파, 관련 역산·공차·수렴 평가 | [crosssection.py](../src/sipi/crosssection.py), [templates.py](../src/sipi/templates.py), [quasistatic.py](../src/sipi/quasistatic.py), 도체·유전체 모델, [line_model.py](../src/sipi/line_model.py), [propagation.py](../src/sipi/propagation.py), 설계·스터디 문서 |
| 공통 네트워크·회로 | 포트 순서·기준 임피던스·네트워크 자료·연결·종단·여기·교환 형식. 여러 물리 모델이 사용 | [network.py](../src/sipi/network.py), [connection.py](../src/sipi/connection.py), [termination.py](../src/sipi/termination.py), [circuit_document.py](../src/sipi/circuit_document.py), [touchstone.py](../src/sipi/touchstone.py) |
| 다른 물리 영역 | 고유 모델 계약을 가진 전원면 전도와 경계가 명시된 3D 해석 | [plane.py](../src/sipi/plane.py), [capacitance3d.py](../src/sipi/capacitance3d.py), [ports3d.py](../src/sipi/ports3d.py) |
| 제품 애플리케이션 | 저장 문서 실행 분배, 요청·결과 결합, 여러 설계를 담는 프로젝트 | [execution.py](../src/sipi/execution.py), [execution_request.py](../src/sipi/execution_request.py), [execution_record.py](../src/sipi/execution_record.py), [project.py](../src/sipi/project.py) |
| 실행 호스트·화면 | 입력폼·그림·파일 접근·프로세스/Worker 수명·취소·오래된 결과 차단·패키징 | [workbench](../workbench/README.md), [cli.py](../src/sipi/cli.py), [project_io.py](../src/sipi/project_io.py), [setup.py](../setup.py) |

이 표는 책임 경계이며 파일 이동 목록이 아닙니다. 예를 들어 `network.py`에는
공통 표현인 `LineNetwork`와 선로 전용 `rlgc_network`/`quasistatic_network`가
함께 있습니다. 전자는 공통 네트워크 계약, 후자는 전송선 전파 영역입니다.
파일명만 보고 통째로 분리할 수 없습니다. 분포 RLGC 사다리 모델의 시간 응답은
선로 영역이지만 일반 여기·종단·네트워크 연결 계약은 재사용할 수 있어야 합니다.
기존 startup·회로 조합도 함수 단위로 검토합니다.

`PowerPlane`은 이미 있는 DC 시트 전도 모델이며 AC 전원망 제품은 아닙니다.
경계가 명시된 `Capacitance3D`는 전체 C[F]를 구하며 단위 길이당 RLGC가 아닙니다.
기존 3D TEM 포트 모델에는 명시적 사면체, 균질 매질, 국소적인 환형 TEM 어드미턴스
포트 두 개, 나머지 벽의 PEC 조건이 필요합니다. 코드가 있다는 이유로 임의 비아·
커넥터·방사·다중 모드 지원을 주장하지 않습니다. 이들은 두 단면의
[차동선 프리뷰](../workbench/PAIR_PREVIEW.ko.md)에 포함되지 않습니다.
기존 구현은 보존하되 검증된 대화형 제품 기능처럼 광고하지 않습니다.

## 의존 방향

사용하는 쪽에서 제공하는 쪽으로 향합니다.

```text
SIPI 화면 / CLI / 로컬 호스트 / 브라우저 Worker
                    ↓
           실행 분배·프로젝트 관리
                    ↓
      전송선 영역 | PI 영역 | 제한된 3D 영역
                    ↓
           공통 자료·네트워크 계약
                    ↓
            필요한 공유 수치 API
```

모든 네트워크 함수가 필드 솔버를 호출해야 한다는 뜻은 아닙니다. 각 물리 영역은
수치 API를 직접 사용할 수도 있습니다. 공유 수치 패키지와 향후 독립 전송선
라이브러리는 SIPI 화면·프로젝트 관리자·제품 전체 실행 등록표를 import하지 않아야
합니다. 제품이 영역별 제공자를 조합합니다. 일반 JSON 검증·유한수 확인·정규화·
자료 계약은 제품 전체 dispatcher에 의존하지 않도록 정리합니다.

전송선 라이브러리는 Python에서 브라우저·파일·프로세스·모델 업로드 없이 사용할 수
있어야 합니다. 전송선 입력 문서와 의미 검증은 라이브러리에 속하지만, 여러 설계를
담는 프로젝트와 실행 환경 관찰·실행 수명 관리는 제품/호스트에 속합니다.
수치 문제의 입력 수락은 도메인이, 실행 시간·프로세스 종료·오래된 응답 차단은
호스트가 담당합니다.

## 실제 추출 전에 풀어야 할 결합

정적 소스 확인으로 찾은 내용이며, 지금 곧바로 독립 추출이 가능하다는 증거는 아닙니다.

1. [__init__.py](../src/sipi/__init__.py)가 전송선·전원면·네트워크 등의 API를 한꺼번에
   import/re-export합니다. 구현을 옮길 때 기존 import를 호환 진입점으로 유지합니다.
   현재 initializer를 그대로 작은 배포판에 복사하면 넓은 의존성도 남습니다.
2. `LineNetwork`와 공통 검증 도우미가 선로 전파와 같은 `network.py`에 있고,
   `ports3d.py`도 이를 import합니다. 파일 전체를 전송선 전용으로 추출하면 3D 소비자도
   단순 결과 표현 때문에 전송선 배포판에 의존하게 됩니다.
3. `template_document.py`는 `circuit_document.py`의 JSON 도우미와 `study.py`의
   템플릿 등록표를 사용합니다. 중립적인 검증·템플릿 등록을 먼저 정리해야 합니다.
4. `project.py`와 `execution_record.py`는 회로·단면 문서·실행 모듈의 private
   도우미를 사용합니다. `project_io.py`도 `execution.py`의 정수 검증에 의존합니다.
   작은 단위로 공통 도우미를 분리하고 검증 규칙을 복제하지 않습니다.
5. `execution_request.py`가 여러 물리 모델을 불러오는 `execution.py`를 통해 구체적
   선로 문서형을 import합니다. 장기적으로 도메인이 문서·입력 수락 정보를 선언하고
   제품이 등록표를 조합하도록 합니다. 현재 등록표는 그대로 유지합니다.
6. 데스크톱 엔진과 화면폼 목록이 모델을 명시적으로 선택합니다. Python API 존재,
   저장 문서 실행, 전용폼 존재, 특정 Worker/native 빌드의 검증은 서로 다른 사실입니다.
   향후 기능 설명 자료도 이를 구분해야 합니다.

## 경계에서 보존할 계약

| 계약 | 이동 전에 보존하거나 명시할 내용 |
| --- | --- |
| 입력 | 기존 schema 식별자·버전, SI 물리 값, 신호·접지 순서, 기하·재료법칙·주파수 범위, 실제 메시·외곽 설정 |
| 전송선 결과 | R[Ω/m], L[H/m], G[S/m], C[F/m], 도체 순서, 모드 및 순방향 여기 물리량의 정확한 의미 |
| 네트워크 결과 | 주파수[Hz], 포트 순서, 양수 기준 임피던스, 안쪽 방향 종단 전류, 기존 `exp(+j omega t)`와 복소수 인코딩 |
| 결과 식별 | 정규화 입력·제어값, 정확한 엔진·의존 아티팩트, 선택 기하·실제 설정. 검증되지 않은 호스트 선언을 검증된 빌드로 취급하지 않음 |
| 실패 | 실패형·부분 결과·거부/실패 표본·검색 이력·자원 제한 원인. 부분 결과를 성공으로 바꾸지 않음 |
| 저장 | 기존 JSON·프로젝트 의미. 미지원 버전은 원문을 보존하며 실행 거부. schema 식별자를 조용히 변경하거나 변환하지 않음 |

다른 제품과의 어댑터는 단위·위상·포트 변환을 명시하고 검증합니다. 같은 패키지군에
속한다고 규약까지 같다고 가정하지 않습니다. 기존 허용오차·fixture·실패 기록·
수렴 조건을 보존합니다.

## 패키징과 구현 순서

현재는 저장소 하나와 기존 `sipi` 배포판을 유지합니다. 이 설계만으로 새 의존성을
추가하거나 전송선 전용 패키지를 설치할 수 있다고 안내하지 않습니다. 향후 배포판
이름과 import 경로는 미정이며, 별도 패키지도 같은 저장소에 둘 수 있습니다.

1. 책임과 실제 결합을 문서화합니다. 이번 작업입니다.
2. 결과·기존 import를 보존하며 중립적인 검증·자료 계약을 분리하고 저장·실패 회귀를 확인합니다.
3. 공통 네트워크 표현과 선로 전파를 나누고, 기존 API·파일을 유지하는 화면 없는 전송선 진입점을 정리합니다.
4. 제품이 전송선·다른 물리 제공자를 조합하게 하고, 정확한 빌드와 검증된 사용 흐름에 따라 호스트별 기능 범위를 명시합니다.
5. 실제 독립 소비자가 필요할 때 전송선 배포판을 검토합니다. UI·프로젝트 없이 격리 설치, 의존성·고지 완결, 기존 API/JSON 호환, 수치·독립 기준·수렴 시험 보존, 설치 아티팩트 검증이 조건입니다.
6. 브라우저 Worker와 Windows 단일 EXE 소비자를 각각 다시 검증합니다. 분리가 단일 EXE·오프라인 계산·기본 브라우저 요구를 취소하지 않으며 브라우저 엔진을 추가로 번들하지 않습니다.

이번에는 문서만 바꿉니다. 2–6단계 구현, 브랜치 병합, 의존성 pin 변경이나 릴리스
준비 완료를 뜻하지 않습니다.
